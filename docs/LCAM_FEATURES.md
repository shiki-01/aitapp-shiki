# LCAM の機能一覧（PC 版）と aitapp への取り込み方針

調査日: 2026-09-25。ユーザーが内蔵ブラウザで LCAM（PC 版）にログインした状態で、メニューを順にクリックして観測した。
観測は読み取りのみ（検索・一覧・詳細の表示）。登録・更新・取消・提出・ログアウト・パスワード変更は一切押していない。

目的: LCAM は単一セッションで、本家でログインすると Worker の登録セッションが切れる。そのため、日常操作を全部 aitapp で
済ませられるようにする。破壊的で「本家でやるべき」ものは、機能名だけ一覧に残し、本家へ飛ぶリンクで済ませる。

凡例（aitapp 列）: ✅ 実装済み / △ 一部 / ❌ 未実装。種別: 参照 / 書込（状態を変える）。

## 0. 観測でわかった仕組み（実装に効く事実）

- **PC 版のメニュー遷移は POST**。全メニューが `postMenuSubmit(form, menuCode, nextPath, '/common/generalPurpose/')` で、
  `POST /portalv2/common/generalPurpose/` に `org.apache.struts.taglib.html.TOKEN` / `headTitle` / `menuCode` / `nextPath` を送る。
  実リンク（GET）で開くとエラーになるのはこのため。
  `worker/src/upstream/lcam/access.ts` の `postPcHomeInitialize`（`menuCode=Z07`）が実 LCAM で通っているので、
  下の表のメニューコードも同じ方式で開ける見込み（**Z07 以外は未検証**）。token は直前のページ HTML から取り、
  ページごとに更新される。並列に投げず、1 リクエストずつ直列にたどる。
- 各ページ内の操作（検索・詳細・ダウンロード）も Struts のフォーム POST。フォーム名・項目名は表の「操作」列に写した。
- **学事システム（`/kyoumu/`）は別アプリで、LCAM セッションから引き渡す**。手順（実測、いずれも 200）:
  1. PC ホームの `home_systemCooperationLink` フォームを `POST /portalv2/home/systemCooperationLink/initialize?renkeiType=kyoumu`
  2. 返る HTML が自動送信フォーム（`action=/kyoumu/portalRedirect.do;JSESSIONID=…`、`loginID`）を持つ
  3. それを POST すると学事システムのメニュー（16 項目）が返る
  4. 以降の画面は `;jsessionid=…` 付き URL への **GET** で取れる（16 項目のうちシラバス・カルテ登録を除く 14 画面で 200 を確認。うち登録系 4 画面は入口の表示のみ）
  URL にセッションが入るので、「セッション付きリンク」を作りやすい（§4）。
- 画面右上に残り時間 `01:30:00`（無操作 1h30m）。
- **ログアウトは絶対にリンクにしない**（押すとセッションが失効する）。

## 5. 「本家へ飛ぶ」リンクの作り方（案。未検証）

- **学事システム系（履修登録・取消・抽選・学籍更新）**: §0 の手順で得た `…/kyoumu/portalRedirect.do;JSESSIONID=…` は
  URL にセッションが入っている。これをユーザーのブラウザで開けば、Cookie なしでそのまま学事システムのメニューに入れる可能性が高い
  （**別 IP・別 UA で通るかは未確認**。LCAM 側は IP/UA 紐付けなしと実測済みだが、学事システムは未測定）。
  リンクは押した時点で Worker が発行する（使い回さない）。
- **LCAM PC 版そのもの（パスワード変更など）**: 認証は Cookie（`JSESSIONID`）で、URL には入らない。Worker はブラウザに別ドメインの
  Cookie を渡せないため、リンク 1 本では入れない。案: Tauri 版では、既存の WebView（Cookie を持つ）に切り替えて開く。
  Web 版では「本家を開く」だけ出して、自分でログインしてもらう（この時点で Worker のセッションは切れる旨を表示する）。
- どの経路でも、開く前に「本家でログインすると aitapp のセッションが切れる場合がある」ことを画面に出す。

## 6. 実装の優先順位（案）

1. **参照系で価値が高く安全なもの**: 学内共有ファイル（PDF）、レポート一覧・参照・提出履歴、施設（空き教室）、
   単位修得情報・カリキュラム、抽選履修登録結果、学内スケジュール（年間行事）、全体時間割、授業/学内連絡の絞り込み・未読・ToDo。
2. **本人の範囲で完結する書込**: レポート提出、学内/授業評価アンケート回答、オフィスアワー申請、個人予定の登録、トピック投稿、個人リンク。
   いずれも不可逆になりうるので、確認画面つき・既定は無効（既存の「不可逆操作を許可」の仕組みに乗せる）。
3. **本家へ飛ぶ**: 履修登録・取消・抽選、学籍情報の更新、教職カルテの登録、パスワード変更。

## 7. 未観測・要確認

- PC 版の授業アンケート・授業評価アンケートの一覧の語彙（0 件だった）。学内アンケートの回答画面（提出済のみだった）。
- Z07 以外のメニューコードを Worker から POST で開けるか、および各画面内の操作（検索フォームの項目名）の実測。
- 学事システムのセッションが LCAM セッションとどう連動するか（LCAM 失効で学事システムも切れるか、単一セッションの制約はあるか）。
- 学事システムの JSESSIONID 付き URL を別 IP・別 UA のブラウザで開けるか。

## 8. この調査で発生した副作用

- 授業連絡「環境と地域共創 第1回 講義資料」と学内連絡「学生生活実態調査（リマインド）」の詳細を開いたため、**既読になった可能性**がある
  （ホームの未読は開く前から 0 件）。
- 学事システムへの引き渡しを 2 回実行し、学事システム側にセッションが 2 つできた（ログアウトはしていない。自然失効を待つ）。
- ユーザーが内蔵ブラウザで LCAM にログインしているため、単一セッションの制約により、**Worker の登録セッションは失効している可能性**がある
  （必要なら aitapp で再登録）。
